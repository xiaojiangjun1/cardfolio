# Cardfolio v1.9 使用与升级说明

本版基于 v1.8 增量开发。继续保留 v1.7.4 的统计口径、导入校验、保存失败保护、双窗口冲突检测、50 条流水分页、搜索光标与 IME 处理。

## 这次增加了什么

1. “我的信用卡”自动显示已匹配产品的官方卡面，图片已嵌入程序，离线可显示。
2. 25 种常见卡、58 条已核实的周期权益模板，包含每月、每季度、每半年、每年及持卡年 / 账单周期。
3. 年费提醒同时显示过去 30 天及未来 90 天。周年日只是预计日期，实际年费仍由你按账单登记，不自动修改实际日期或金额。
4. 循环权益可登记报销、标记本期已使用、恢复提醒、编辑额度与周期。
5. 普通旧报销额度继续保留在原页面；新规则不会自动套到历史流水。

## 启用官方权益

在“我的信用卡”点击“查看权益 / 启用提醒”，阅读来源、金额、周期和登记条件，勾选所需项目后启用。提醒不会替你在银行登记权益，也不代表你已经符合消费门槛。

也可以打开“报销额度管理”（手机：更多 → 报销权益），选择卡片启用，或新增自定义循环权益。

资料核实日期：2026-11-09。资料是打包时的快照，不会在后台自动抓取银行资料；后续权益变动可自行编辑或更新程序。新模板不会静默改写已经启用的个人规则。

## 周期怎么区分

| 规则 | 例子 | 处理 |
|---|---|---|
| 日历月 | 部分餐饮、数字订阅额度 | 每月 1 日重置 |
| 日历季度 | Hilton Surpass | 1 / 4 / 7 / 10 月开始 |
| 日历半年 | Hilton Aspire Resort、Gold Resy | 1—6 月 / 7—12 月 |
| 日历年 | 部分航司杂费 | 1 月 1 日至 12 月 31 日 |
| 持卡 / 账户年度 | Venture X、Sapphire 旅行或酒店额度 | 启用时确认本人账户实际周期起点 |
| 账单周期 | AT&T Points Plus 消费门槛返还 | 必须填写账单起点，不能按自然月推定 |

Wells Fargo Autograph Journey 的续年周期从年费入账后的次月 1 日开始；请以实际入账日确定起点。Sapphire 等账户可能按周年后的首个账单日重置，开卡日只是表单初始建议，必须按账户调整。

对于 29 / 30 / 31 日起点，程序会处理短月和闰年。若银行改变出账日期，请同步修改规则。跨月消费最终归属以银行条款为准。

## 额度、报销和现金不会混在一起

- 启用提醒不自动增加现金收入，不会自动生成已到账奖励。
- “登记报销”会使用现有的报销额度与流水表单，关联到对应周期。
- 已到账及已申请待到账会占用本周期额度；部分到账仍沿用原有口径。
- 旧流水不按相同卡名或相似权益名称自动匹配。需要时，请在原流水手动选择明确对应的周期额度。
- “本期已使用（不记账）”只关闭这期提醒；适用于已使用但暂不记账的额度，可随时恢复。
- Uber Cash、预订折扣、房券资格等是非现金权益；只能跟踪使用，不会直接加到现金收支。
- 下一个周期自动显示新额度，不会复制上一期的到账记录。
- 删除循环提醒会保留历史额度和已登记报销；关卡或产品发生变化时，相关规则暂停，避免把旧卡权益套给新产品。

## 年费最近一个月

过去 30 天以内的预计周年日仍保留，标记为“最近一个月”。若已经登记了附近日期的实际年费，会在备注中显示实际入账日期与金额，方便核对延迟入账。

这只是提醒，不代表逾期，也不生成应付账款。程序不会把周年日写成实际 postedDate，不会自动收取或记入预计金额。无年费且未手动指定年费日的卡不生成普通年费提醒。

## 卡面范围与清晰度

按本次选择先覆盖常见卡，并非完整的数百款产品目录。所有内置图片均从发卡行或品牌官方页面取得，未生成仿制卡面；图像来源及原始像素列在 SOURCES_v1_9.md。

官方原图大小约 250—1600 像素宽，部分官方只公开标准小图，保留其原分辨率，没有放大后冒称高清。相同产品可能有不同年份、联名版或限定配色，默认使用本次收集的官方展示图。

未匹配产品可手动选择对应官方产品，或者上传不含本人完整卡号、CVV 等信息的通用卡面。上传图片仅保存在本机并随 JSON 导出，不会上传至网络。图片会转成受限大小的栅格图，超出存储空间时沿用原保存失败保护。

## 安装和升级

1. 先从旧版导出完整 JSON。
2. 解压 Cardfolio_v1_9_PWA.zip，将其中 index.html、sw.js、manifest.webmanifest、icons、README 和两个点文件等放到原 GitHub 仓库根目录，替换程序文件。
3. 必须一起替换 sw.js；只换 index.html 可能仍停留在旧离线缓存。
4. 等 GitHub Pages 部署完成，在 App 中检查更新并安装。
5. 同一网址更新不会主动清空本地数据。新设备或 Safari / 主屏幕 App 数据不一致时，手动导入备份。
6. 不要把私人 JSON / CSV 备份上传到公开仓库。

独立 HTML 直接打开也可使用，卡面不依赖网络。新版本文件名与路径可能对应不同的 file:// 存储，请先导出旧数据再导入。iPhone 建议使用 HTTPS PWA，文件 App 的 HTML 预览不保证执行完整脚本。
