# 已知限制与 iPhone 真机验收

## 已验证范围

Windows Chrome 155.0.8059.79，桌面和 Chromium 触屏 / 移动视口模拟。PWA 使用本机 localhost 的真实 Service Worker、CacheStorage 和离线网络模拟；这不等于已完成公开 GitHub Pages 或真实 iPhone Safari 的端到端验收。

未连接真实 iPhone、Android 手机、Safari / WebKit 真机、Apple 原生输入法或系统软键盘。请勿把合成 CompositionEvent、缩短视口、文件输入注入、Web Share API 桩当成这些原生环境的测试结果。建议 iOS 16+ 与近期版本 Android / Chrome；更老浏览器未逐一验证。

## 使用边界

- 本地存储不是云端备份；系统空间回收、清理网站数据或删除 App 可能导致丢失。隐私浏览和存储权限受限环境也不能保证持续保存。
- `file://` 的存储归属由浏览器决定；换路径或文件名后请手动导入 JSON。iOS 文件预览不能作为完整独立网页运行环境。
- 浏览器关闭 / 崩溃 / 系统终止进程时，未保存表单不能保证恢复；正常关闭表单有确认，窗口尺寸变化会保留同一个表单节点。
- 更新页面不清空本地记录。更换 origin（域名、协议、端口）需要手动迁移。相同 GitHub 用户域名下的不同路径共享 origin，不适合作为互相隔离的数据副本。
- 离线缓存必须先在线完成一次。用户仍打开旧版本时，更新通常等待安装；有未保存表单的窗口会保留当前内嵌程序，保存后应点击更新提示重新打开。
- 网页只能确认发起下载 / 完成分享调用，不能确认文件最终被系统保存到哪个位置。最近备份时间在界面中明确标为“最近发起导出 / 分享”。
- 没有自动跨设备同步、合并、银行余额读取、积分扣减、转点或兑换折现。报表积分是登记奖励合计。
- 除原有 50 条流水分页外，积分项目目录和卡片目录仍按原设计显示；项目 / 卡片规模远大于常见家庭使用量时未进行专门压力测试。
- GitHub Pages 托管及文件下载会正常访问 GitHub 的服务器；Cardfolio 不上传记账内容。用户主动选择的分享目的地按该服务自身规则处理文件。
