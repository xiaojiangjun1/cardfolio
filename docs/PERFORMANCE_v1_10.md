# Cardfolio v1.10 性能对比

日期：2026-11-09。CPU AMD Ryzen 5 5600X 6-Core Processor；Windows_NT 10.0.26200；Chrome 155.0.8059.79；Node v24.22.1。

## 方法

相同机器、相同浏览器进程，顺序建立隔离上下文，对保留的 v1.9 和 v1.10 运行相同夹具。5,000条流水 / 20张卡，宽搜索匹配分页50条，与唯一关键字命中第5,000条轮换；25轮预热、40轮计时。计时同步 renderLedger，包含过滤与当前页DOM生成，排除布局绘制和异步观察者。不是整页加载 / 手机真机操作耗时。

| 版本 | 视口 | 中位 ms | P95 ms | 宽搜索中位 ms | 唯一搜索中位 ms |
|---|---|---:|---:|---:|---:|
| v1.9-baseline | 1440x1000 desktop | 4.8 | 7.8 | 7.6 | 2.1 |
| v1.10 | 1440x1000 desktop | 4.9 | 7.8 | 7.7 | 2.2 |
| v1.9-baseline | 390x844 touch | 5.6 | 9.2 | 9 | 2.2 |
| v1.10 | 390x844 touch | 5.75 | 9.2 | 9.05 | 2.2 |

本次差异很小，未观察到明显搜索渲染回退，不能把微小耗时差异视为稳定提速或变慢。源码未改动 renderLedger、paged 或统计函数。卡面DOM仅在信用卡页面创建，图片使用lazy / async decode与复用的blob URL，流水继续每页50条，搜索和导出仍覆盖全部数据。

HTML 从 2.13 MiB 增至 4.87 MiB，增量来自内置卡面及来源元数据。首次下载 / 缓存有必要开销；离线不再需要逐张下载外部图片。没有将此同步耗时与以前不同机器 / 口径的“14ms”“833ms”直接比较。

复现：node tests/benchmark-v1.10.cjs。原始40次样本在 artifacts/v1.10-benchmark-results.json。
