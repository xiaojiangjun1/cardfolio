# v1.7.4 → v1.8 数据迁移

## 数据兼容约定

| 内容 | v1.8 行为 |
|---|---|
| 数据格式 / 主存储键 | 仍为 v6 / `cardfolio_data_v6` |
| v1.x 备份 | 沿用 v1.7.4 的验证、规范化、历史迁移 |
| 历史申请 / 开卡日期 | 已有 opened 优先；空 opened 才用 applied；approved 不替代 |
| 实际日期与登记日期 | postedDate 用于时间线；date 只是登记日期；旧年度统计回退规则不变 |
| 历史报销 actualAmount = 0 | 缺少明确标记时，继续使用旧版申请额回退；不自动重新解释 |
| 明确输入报销 0 | `creditActualProvided: true`，到账计 0 |
| 部分到账 | 已到账与剩余待兑现沿用原计算 |
| 副卡 Bonus | 奖励归主卡；actualPoints 不再乘副卡数；家庭统计不重复 |
| 产品变动 | 保留日期生效、编辑 / 删除后重算及 `_productState` |
| 积分显示顺序 | `visualOrder` 随 JSON 导入和导出，保持用户偏好 |
| PWA / 导出时间 | 应用缓存与本机导出时间单独保存，不改业务字段含义 |

## 迁移操作

1. 在旧版导出完整 JSON，确认文件可找到。
2. 在目标 v1.8 先导出当前记录，防止覆盖后无法恢复。
3. 点击「更多 → 备份与说明 → 从文件导入 JSON」。
4. 选择文件；阅读数量及覆盖提示，再确认。
5. 核对 P1 / P2、尾号、开卡日、主副卡关系、到账与待兑现、项目排序。
6. 重新导出一份目标端 JSON；确认系统已保存。

导入不是合并。异常 JSON、错误日期、重复 ID 或错误卡片 / 副卡 / 报销关联会被拒绝；取消覆盖会保留现有数据。成功替换前，沿用原机制保存上一份可读数据快照；它和主数据在同一设备，不能代替外部备份。

## 手机与主屏幕 App

在电脑、Safari、主屏幕 App 中分别检查记录。即使地址相同，也不要依赖它们共享 localStorage。首次安装主屏幕 App 后，使用系统「文件」选择器手动导入。导出后通过下载或系统分享保存，再从目标端选择该 JSON。

系统文件选择器、下载和分享分支已在 Chromium 自动化 / API 模拟中验证；iPhone「文件」原生选择、Safari 下载面板、主屏幕文件分享仍须按真机清单验收。

## 回退

保留旧 HTML 和升级前 JSON。若需要回退，可用旧版先查看自己的备份；不要让旧版和新版同时修改同一浏览器里的同一存储键。恢复前先分别导出两端数据。没有执行向旧版降级的数据破坏性转换。
